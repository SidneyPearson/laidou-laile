「来都来了」公开端改进方案清单

基于用户视角全流程走查（首页 → 定位/选城市 → 灵感浏览 → 今日计划）与 API 实测。共 10 项（底部导航「收藏/个人中心」经确认保留、由用户自行完善，未列入）。

P0 · 影响信任与主流程 P1 · 体验断层 P2 · 打磨项
# 优先级 问题 现状 / 影响 改进方案
1 P0
「美食探店」分类无内容时误导为故障
 上海「美食探店」（id food）是唯一空分类：后端返回 503 NO_VERIFIED_SPOTS，前端 loadAllSpots 吞掉服务端文案、统一显示「地点暂时加载失败，请稍后重试」+「重新加载」，用户反复重试以为服务挂了。其余 7 个分类均有内容。 后端区分「城市不支持(404)」与「分类为空(200+空)」，前端空态显示 「该分类内容筹备中」，而不是可重试的错误态。
2 P0
首页「滑动解锁」静默清空今日计划
 handleFreshStart 直接 clear()，手滑一下精心选的 6 个地点全没了，无任何确认。 计划非空时滑动后 弹确认，或改为普通进入 + 单独的「重新开始」入口。
3 P1
探索页看不到距离 / 雨天不生效
 首页有「923m / 2.1km」，探索页请求不传 lat/lng 与 isRainy，距离消失、排序不贴合位置、雨天不过滤。 探索页请求带上已授权真实坐标与 isRainy，卡片 meta 补距离。
4 P1
地点更新后只能「手动删了重加」
 suggest-order 对旧 POI 返回 POI_MISMATCH，用户需自己找出过期地点、删除、重新查找、重新加入。 检测到 mismatch 时提供 「一键刷新地点信息」（按 hotspotId 重拉 POI/坐标）。
5 P1
清空计划用原生 confirm
 精致黑底 UI 里蹦出系统级确认框，出戏。 换成与 SpotDetailSheet 同语言的 底部确认弹层。
6 P1
探索页串行分页拉全量，加载慢
 切一次分类 while 循环最多 10 次串行请求（每页 6 条），弱网下长时间转圈。 服务端支持更大 limit / all=true 一次拉全，或改成分页「加载更多」。
7 P2
首页画像卡图片全空
 /api/home/personas 返回的 4 张卡 imageUrl 全为 null，卡片裸奔。 后台补图，或前端做 渐变兜底。
8 P2
未支持城市静默降级 demo 数据
 定位到拉萨 → 404 → 前端悄悄切本地 demo，地点还不能加计划，体验断层无提示。 城市名旁加 「内容筹备中」徽标，demo 卡片直接标「示例」。
9 P2
英文错误信息透出
 参数异常时透出 zod 原文（"Required"、"Array must contain…"）。 zodErrorToBody 统一 映射成中文。
10 P2
行程单无法带走
 今日计划只能截图，缺分享/传播出口。 基于现成的城市票根，加 「生成今日行程图」。
建议先动 P0 两条（「美食探店」空态误导 + 滑动解锁清空计划）。底部导航死入口经确认保留、由用户自行完善。
