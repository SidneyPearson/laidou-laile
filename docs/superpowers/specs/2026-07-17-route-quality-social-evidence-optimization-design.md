# 路线质量与网红美食证据优化设计

## 1. 目标

本次优化同时治理路线基础质量和网红美食证据，解决以下已复现问题：

- 热门区域出现 `NO_POIS_FOUND`；
- 学校、培训中心、服务站等无关地点进入游玩路线；
- “5个地点”“TOP3”等文案与实际地点数量不一致；
- 普通连锁餐厅被包装为网红美食；
- 美团、抖音、小红书标签没有可核验的公开网页证据。

最终目标是让地点真实、类型相关、距离合规、数量准确，并让每一个平台热门声明都能追溯到公开来源。

## 2. 范围与原则

### 2.1 本次包含

- 高德 POI 多策略召回与结果过滤；
- 路线和美食榜单的数量规则；
- Tavily 公开网页搜索及门店证据匹配；
- 美食排序与高德补位；
- 接口证据字段和前端来源展示；
- 原 10 组组合的自动化与端到端回归验收。

### 2.2 本次不包含

- 绕过美团、抖音、小红书的登录、反爬或访问限制；
- 抓取非公开内容；
- 将搜索摘要当作评分、销量或打卡量的精确事实；
- 为凑足数量而放宽地点类型、距离或证据真实性要求。

### 2.3 数据职责

- 高德是门店名称、地址、坐标、距离和基础评分的事实来源。
- Tavily只检索公开网页中的美团/大众点评、抖音和小红书证据。
- 规则层负责过滤、排序、数量和最终一致性。
- AI只负责路线主题、简短推荐理由和自然语言表达，不能创造或修改事实字段。

## 3. 总体架构

```text
用户选择
  → 高德多策略召回
  → 类型、距离和营业状态过滤
  → Tavily公开网页证据搜索
  → 门店名称匹配与证据评分
  → 规则排序、补位和数量裁剪
  → AI生成主题与推荐理由
  → 返回前硬校验
  → 前端展示
```

该流程采用“规则兜底＋AI编排”。任何硬规则都不能被AI输出覆盖。

## 4. 路线质量治理

### 4.1 多策略召回

每个偏好先执行精确搜索。候选不足时依次执行：

1. 品类同义词搜索，例如“地方菜”扩展为“特色菜、老字号、本地菜”；
2. 高德类型分类搜索，补偿关键词搜索遗漏；
3. 热门商圈或景点名称与品类组合搜索；
4. 为召回临时扩大搜索范围，但最终结果仍按用户选择的最大距离过滤。

不得为了补足数量返回超距地点。

### 4.2 地点过滤

建立游玩地点拒绝规则，至少拦截：

- 学校、培训中心和教育机构；
- 政务、办公和内部服务机构；
- 售后服务站、发行站和单纯办事网点；
- 居民区、普通写字楼及无游览属性的市场；
- 与用户偏好明显不相符的地点。

过滤同时参考高德类型码、名称关键词和用户选择的偏好。名称黑名单只是补充，不能替代类型校验。

### 4.3 数量规则

- 1小时：目标2家或2个地点；
- 2小时：目标3家或3个地点；
- 半天：目标4至5家或地点；
- 一天：目标5至6家或地点。

候选不足时返回实际合格数量，不重复地点、不放宽硬条件、不虚构地点。

纯美食场景返回 `food_list`，展示为“附近美食榜单”，不包装成游玩路线。

### 4.4 文案一致性

“共N家”“N个地点”“TOP N”只能由最终响应数组长度生成。AI提示词和AI响应不得成为数量来源。

若最终只有两家，文案必须显示“精选2家”或“共2家”，不能显示“TOP3”。

## 5. 网红美食证据

### 5.1 搜索策略

Tavily使用免费计划的 `basic` 搜索。查询包含城市、商圈或景点、品类，以及美团/大众点评、抖音、小红书、网红美食等关键词。

单次美食榜单生成最多消耗一次搜索 credit。同一区域结果按现有缓存策略复用；超时、401、429、5xx或格式异常时立即降级，不执行收费重试。

### 5.2 合法证据

证据必须同时满足：

- URL域名属于美团/大众点评、抖音或小红书；
- 标题或摘要能够匹配到具体高德门店；
- 门店名称匹配达到配置的置信度阈值；
- 证据链接、标题和平台信息完整。

只有商圈级“美食推荐”但无法匹配具体门店的内容不能作为门店证据。

### 5.3 门店名称匹配

匹配前统一处理全半角、空格、分隔符、括号及常见门店后缀。核心品牌名和分店区域共同参与匹配：

- 核心品牌和分店均匹配：高置信度；
- 核心品牌匹配、分店不明确：中置信度，仅用于辅助排序；
- 只有品类或商圈匹配：不形成门店证据。

同一门店的多条证据合并；多平台交叉出现提高得分，但不重复占用榜单名额。

### 5.4 排序规则

美食候选采用100分制：

- 平台证据：40分；
- 高德评分：25分；
- 品类相关性：20分；
- 距离：10分；
- 普通连锁惩罚：最多扣5分。

多平台交叉证据高于单平台证据。没有平台证据的星巴克、肯德基、DQ等普通连锁品牌应降权；若其确有可靠平台证据，可按实际得分参与排序。

### 5.5 平衡模式

榜单优先展示有可靠平台证据的餐厅。数量不足时使用高德高分且品类相关的餐厅补位，并明确标记为“高德高分补充”。

没有证据时不得显示“小红书推荐”“抖音热门”“美团口碑”等平台声明。

## 6. 接口设计

每个地点新增或完善以下字段：

```ts
type RecommendationType = 'social_hot' | 'amap_fallback'

interface SocialEvidence {
  platform: '美团' | '抖音' | '小红书'
  title: string
  url: string
  confidence: number
}

interface RouteStop {
  recommendationType?: RecommendationType
  socialScore?: number
  socialEvidence?: SocialEvidence[]
  rankingReason?: string
  evidenceSummary?: string
}
```

约束如下：

- `social_hot` 必须至少包含一条合法 `socialEvidence`；
- `amap_fallback` 不得展示平台热门标签；
- `socialScore` 只表达证据排序权重，不冒充平台官方分数；
- 旧客户端忽略新增可选字段后仍能正常展示路线。

## 7. 前端展示

纯美食页每家餐厅展示：

- 综合排名、名称和简短排序理由；
- 高德评分、距离和品类；
- 真实的平台来源标签；
- 可点击的公开证据链接；
- “平台热门”或“高德高分补充”标识。

没有平台证据时不显示空标签或暗示性文案。页面统一使用实际地点数量生成标题和徽标。

路线场景继续展示多地点方案，但路线卡片中的地点数量、标题数量和实际数组长度必须一致。

## 8. 错误处理与降级

- Tavily不可用：继续生成高德榜单，所有地点标为 `amap_fallback`；
- 社交证据无法匹配：不保留平台标签，不能影响地点真实性；
- 单一搜索无结果：执行同义词、类型和商圈组合召回；
- 合格候选不足：返回实际数量并设置明确的 `fallbackReason`；
- 最终没有合格地点：返回现有 `NO_POIS_FOUND`，同时日志记录各阶段候选数和淘汰原因。

前端空状态提示用户扩大距离或放宽品类，不能笼统归因于网络问题。

## 9. 返回前硬校验

响应发送前必须检查：

1. 地点类型与用户偏好相符；
2. 每个地点均在用户距离限制内；
3. 所有数量文案等于最终数组长度；
4. 所有平台标签均有合法证据；
5. 同一方案内没有重复地点；
6. 时间预算能容纳最终地点和步行时间。

不合格地点直接移除。移除后重新生成数量文案；不得让AI重新补写未经核验的地点。

## 10. 实施批次

### 第一批：路线质量治理

- 完成多策略召回；
- 完成无关地点过滤；
- 修复数量规则和动态文案；
- 修复热门区域异常空结果；
- 增加相关单元测试和原10组回归脚本。

### 第二批：平台证据与展示

- 完善Tavily搜索及门店匹配；
- 落地100分排序和高德补位；
- 返回证据字段；
- 完成前端标签、链接和推荐类型展示；
- 完成证据真实性测试和端到端验收。

第一批通过后再合入第二批，便于定位质量回归和控制免费搜索额度。

## 11. 测试与验收

### 11.1 自动化测试

- POI类型码与名称拒绝规则；
- 同义词及分类召回；
- 距离和时间预算过滤；
- 最终数量和全部展示文案一致；
- 门店名称规范化及置信度边界；
- 平台域名识别和非法证据拒绝；
- 多平台证据合并；
- Tavily失败、限额和缓存降级；
- `social_hot` 与证据数组的一致性；
- 旧接口字段兼容性。

### 11.2 端到端验收

重新执行已记录的10组组合，并达到：

- 不再推荐学校、培训中心、服务站等无关地点；
- 宽窄巷子和北京路能够正常召回，或返回准确且可解释的缺失原因；
- 所有“共N家”“TOP N”和地点徽标与实际数量100%一致；
- 有平台标签的餐厅均有可点击证据；
- 无平台证据的餐厅明确标为“高德高分补充”；
- 自动化测试、构建和本地端到端测试全部通过；
- 至少8组达到“通过”，其余组合不得存在错误推荐或虚假平台标签。

## 12. 上线门槛

两个批次分别提交、分别验收。任一批次出现以下情况不得发布：

- 类型或距离硬规则回归；
- 数量文案不一致；
- 平台标签没有对应证据；
- Tavily不可用导致整个路线接口失败；
- 自动化测试或构建失败。
